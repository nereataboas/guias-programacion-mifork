# TEMA 1. Clases y objetos

## 1. ¿Cuáles son las cuatro características básicas de la programación orientada a objetos? Describe brevemente cada una

Las cuatro características básicas de la POO son:

Encapsulación: consiste en agrupar datos (atributos) y comportamiento (métodos) en una misma entidad (clase), ocultando los detalles internos y exponiendo solo lo necesario.

Abstracción: permite representar entidades del mundo real de forma simplificada, quedándonos solo con las características relevantes.

Herencia: permite crear nuevas clases a partir de otras existentes, reutilizando código y estableciendo relaciones jerárquicas.

Polimorfismo: permite que un mismo método tenga comportamientos distintos dependiendo del objeto que lo invoque.

## 3. Los paradigmas anteriores a la POO, ¿Qué es la **programación estructurada**? y, todavía mejor, ¿Qué es la **programación modular**?

Programación estructurada: organiza el código usando estructuras de control como secuencia, selección (if) e iteración (while, for), evitando saltos incontrolados como goto.

Programación modular: divide el programa en módulos o funciones independientes, cada uno con una responsabilidad concreta, facilitando mantenimiento y reutilización.

# TEMA 2. Encapsulación

## 1. En Programación Orientada a Objetos (POO), ¿Qué buscan la **encapsulación** y **la ocultación** de información? Enumera brevemente algunas ventajas de la ocultación de información.

La encapsulación busca agrupar los datos de un objeto junto con los métodos que operan sobre ellos, controlando el acceso a esos datos.
La ocultación de información consiste en impedir el acceso directo a los detalles internos de un objeto desde el exterior.

Ventajas:
Evita modificaciones incorrectas del estado interno.
Reduce dependencias entre clases.
Facilita el mantenimiento y la evolución del código.
Permite cambiar la implementación sin afectar al uso.
Ayuda a mantener las invariantes de clase.


## 2. ¿Qué se entiende por la **interfaz pública** de un objeto o clase en POO? Describe brevemente cómo se relaciona con la ocultación de información.

La interfaz pública es el conjunto de métodos y atributos accesibles desde fuera de la clase (public).
Define qué puede hacer un objeto, pero no cómo lo hace.

Se relaciona con la ocultación porque:
Solo la interfaz pública es visible.
La implementación interna queda oculta (private).
El usuario de la clase no depende de los detalles internos.


## 3. Brevemente: ¿Por qué hay que ser conscientes y diseñar con cuidado la **interfaz pública** de una clase? ¿Es fácil cambiarla?

Porque la interfaz pública es un contrato con el resto del programa.
Cambiarla suele ser difícil y costoso, ya que:
Afecta a todas las clases que la usan.
Puede romper código existente.
Por eso debe diseñarse con cuidado desde el principio.


## 4. ¿Qué son las **invariantes de clase** y por qué la ocultación de información nos ayuda?

Las invariantes de clase son condiciones que siempre deben cumplirse para que un objeto sea válido (por ejemplo, un radio no negativo).

La ocultación ayuda porque:
Impide cambios directos en los atributos.
Obliga a modificar el estado solo mediante métodos controlados.
Garantiza que las invariantes se mantengan siempre.

## 21. ¿Qué son las clases "wrapper" en un lenguaje de programación orientado a objetos? ¿Cómo se hace? ¿Es un proceso automático? ¿Qué ventajas tienen? ¿Todos los lenguajes orientados a objetos tienen tipos primitivos y necesitan wrappers? 

Las clases wrapper (o clases envoltorio) son clases que encapsulan un tipo primitivo dentro de un objeto.

En Java, por ejemplo:
Tipo primitivo	       Clase Wrapper
int	                    Integer
double	                Double
char	                Character
boolean	                Boolean
long	                Long
float	                Float
short	                Short
byte	                Byte

Un wrapper permite tratar un valor primitivo como un objeto.

Hay dos formas de hacerlo:
1.Manualmente
Integer numero = new Integer(5);   // Forma antigua (ya no recomendada)
2.Automáticamente (Autoboxing)
Integer numero = 5;  // Autoboxing automático
Y al revés:
int n = numero;  // Unboxing automático
Desde Java 5 el proceso es automático gracias al mecanismo de autoboxing y unboxing.

Ventajas:
Permiten usar tipos primitivos en estructuras que trabajan con objetos (por ejemplo ArrayList<Integer>).
Proporcionan métodos útiles:
Integer.parseInt("123");
Double.compare(a, b);
Permiten valores null (un primitivo no puede ser null).
Son necesarios en el uso de genéricos en Java.

No todos los lenguajes OO necesitan wrappers, depende del lenguaje:
En Java sí existen primitivos separados de objetos.
En C# también existen, pero el lenguaje integra mejor ambos conceptos.
En Python no existen tipos primitivos reales: todo es objeto.
En Ruby tampoco hay primitivos separados.
Por tanto, no todos los lenguajes orientados a objetos necesitan wrappers. Solo aquellos que distinguen entre tipos primitivos y objetos.

# TEMA 3. Excepciones

## 1. Empecemos un tema sobre control de errores en lenguajes de programación, con algo básico. En C, donde no existen las excepciones, pongamos un ejemplo de una raíz que toma número flotante positivo. Queremos controlar el error si la función recibe un número negativo. El usuario debe ser informado pero desde fuera de la función `raiz` ¿Cómo indicamos ese error?. Enumera dos opciones diferentes de diseñar, poniendo un ejemplo de código de cada una.

En C no existen excepciones, así que el error debe indicarse mediante el valor de retorno o mediante parámetros adicionales.
Supongamos:
#include <stdio.h>
#include <math.h>

Opción 1: Devolver un valor especial
Si el número es negativo, devolvemos por ejemplo -1 (o NAN).
float raiz(float x) {
    if (x < 0) {
        return -1.0;  // valor especial indicando error
    }
    return sqrt(x);
}
int main() {
    float resultado = raiz(-9);

    if (resultado < 0) {
        printf("Error: no se puede calcular la raíz de un número negativo\n");
    } else {
        printf("Resultado: %f\n", resultado);
    }

    return 0;
}
Problema: -1 podría ser un resultado válido en otras funciones.

Opción 2: Usar parámetro adicional como indicador de error
Se pasa un puntero que indique si hubo error.
float raiz(float x, int *error) {
    if (x < 0) {
        *error = 1;
        return 0;
    }
    *error = 0;
    return sqrt(x);
}
int main() {
    int error;
    float resultado = raiz(-9, &error);

    if (error) {
        printf("Error: número negativo\n");
    } else {
        printf("Resultado: %f\n", resultado);
    }

    return 0;
}
Ventaja: separa claramente el resultado del estado de error.

## 3. Reescribe el mismo ejemplo de raiz, pero en Java, metiendo ese método en una clase `Calculadora` y llama a dicho método desde el método `main`, mostrando cómo se puede controlar desde fuera.

class Calculadora {

    public double raiz(double x) {
        if (x < 0) {
            throw new IllegalArgumentException("Número negativo");
        }
        return Math.sqrt(x);
    }
}

public class Main {
    public static void main(String[] args) {
        Calculadora calc = new Calculadora();

        try {
            double resultado = calc.raiz(-9);
            System.out.println("Resultado: " + resultado);
        } catch (IllegalArgumentException e) {
            System.out.println("Error: " + e.getMessage());
        }
    }
}
Se controla el error desde fuera del método raiz.

## 5. ¿Qué ventajas tiene frente a C, la **"propagación natural"** de las excepciones a través de la pila (*stack*) de llamadas?

No hay que comprobar errores manualmente tras cada llamada
Propagación automática por la pila
Código más limpio
Separación clara entre lógica y errores
Información detallada del error


## 6. En orientación a objetos, ¿las excepciones suelen ser objetos? ¿Qué ventajas tiene esto en términos de encapsulación? ¿Podemos entonces crear excepciones personalizadas?

Sí. En Java son objetos que heredan de Exception.

Ventajas:
Encapsulan información
Pueden tener atributos propios
Podemos crear excepciones personalizadas

Ejemplo:
class NumeroNegativoException extends Exception {
    public NumeroNegativoException(String mensaje) {
        super(mensaje);
    }
}

Un objeto excepción contiene:

Causa (si existe)
Esto es muchísimo más potente que un simple -1 en C.


## 8. En Java, sobre el bloque **"try-catch"**, ¿se pueden tener más de un bloque `catch`? ¿cuántos bloques `catch` se ejecutan?

Sí.
try {
   ...
} catch (IOException e) {
   ...
} catch (IllegalArgumentException e) {
   ...
}
Solo se ejecuta un único catch: el primero compatible con la excepción lanzada.
